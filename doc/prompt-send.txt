*prompt-send.nvim* *prompt-send*  Send prompts with @references

Write prompts in Neovim's `:` command line, reference Neovim content with
`@reference`, and send the resolved prompt to a tmux pane or any command.

This plugin is AI-generated, with zero hand-written code. A human only
directed and reviewed it. Treat it accordingly.

- |:PromptSend| resolves @references and sends the prompt.
- |:PromptTmuxPane| chooses the tmux pane that receives prompts.
- Built-in references `@buffer`, `@file`, `@select`, `@diagnostic`,
  `@gitdiff`, `@N`, plus your own.
- @reference completion; works directly from Visual mode.

==============================================================================
SETUP                                                      *prompt-send.setup*

>lua
  require('prompt-send').setup({
      send       = nil,   -- nil = tmux sender; 'terminal' = Neovim terminal
      enter      = true,  -- append Enter to the tmux sender
      stdin      = false, -- pass prompt via stdin (string send only)
      pane       = nil,   -- tmux pane to send to; nil = auto-scan
      agents     = { 'opencode', 'claude', 'codex', 'aider', 'gemini',
                     'crush', 'goose', 'cursor-agent', 'openhands' },
      references = {},    -- add or override @references
  })
<
All keys are optional. Requiring the module already applies these defaults.

send                                                        *prompt-send.send*

    A string or function used to send the resolved prompt.

    - string:   split on whitespace into argv; never invokes a shell.
    - function: called with the resolved prompt, returns a string or an
                argv (list of strings). The function places the prompt
                itself, so `stdin` does not apply.

    The command's stdout is discarded; only its stderr is kept, and shown as
    an error notification when the command exits non-zero. A successful send
    is silent. This plugin does not read a reply.

    `send = 'terminal'` is a reserved value that sends into a Neovim
    |:terminal| buffer instead of running a command — for a TUI running
    inside Neovim. It writes to a terminal whose title matches `agents`, or
    the most recent one otherwise; pin one with |:PromptTerminal|.

    The default (`nil`) is the built-in tmux sender, which is just a
    function:

>lua
      send = function(prompt)
          return { 'tmux', 'send-keys', '-t', pane, prompt, 'Enter' }
      end
<
    The target pane is the one pinned with |:PromptTmuxPane| or, by default,
    the auto-scan — see |prompt-send.pane| and |prompt-send.agents|.

pane                                                        *prompt-send.pane*

    Which tmux pane the built-in sender types into. Defaults to `nil`, which
    scans the panes on each send: it prefers one that looks like an agent
    (see `agents`), otherwise the first non-Neovim pane. Set a pane id (e.g.
    `"%2"`) to pin one; |:PromptTmuxPane| overrides it for the current
    session.

agents                                                    *prompt-send.agents*

    Names used to spot an agent pane when `pane` is `nil`. Each pane's
    `pane_current_command` and `pane_title` are matched against this list,
    first match wins. If nothing matches, the first non-Neovim pane is used.
    Set `agents = {}` for that older behavior.

enter                                                      *prompt-send.enter*

    Whether the built-in tmux sender appends `Enter`. Ignored when `send`
    is set.

stdin                                                      *prompt-send.stdin*

    How the prompt is passed when `send` is a string. `true` writes it to
    the command's stdin and closes it; `false` appends it as the last
    argument. Ignored for a function `send` and the built-in tmux sender.

references                                            *prompt-send.references*

    Table mapping a name to a function with no arguments that returns a
    string. Merged over the built-in references; same name overrides.

>lua
  require('prompt-send').setup({
      references = {
          git = function() return vim.fn.system('git diff') end,
      },
  })
<
    A name may contain letters, digits, `_` and `-`. A reference has failed
    when the call raises an error or returns `nil`; then nothing is sent and
    the error is shown. An empty string is a success, and an unknown @name is
    left as-is.

==============================================================================
COMMANDS

:PromptSend {prompt}                                             *:PromptSend*

    Send a prompt, replacing every @reference first. Works from Visual
    mode; the leading `'<,'>` is handled for you.

>vim
    :PromptSend check @buffer
    :'<,'>PromptSend explain @select
    :PromptSend what is wrong here: @select @diagnostic
<
    Typing `@` completes reference names. `@@` escapes an `@` — `@@buffer`
    is sent as the literal `@buffer` — and `@N` inserts a newline (see
    |prompt-send-@N|). Unknown @names are left as-is, but if a known
    reference fails, nothing is sent and the error is shown.

:PromptTmuxPane [pane]                                       *:PromptTmuxPane*

    No argument  open a picker listing the panes.
    `auto`       prefer an agent pane, else the first non-Neovim pane.
    A pane id    always send there, e.g. `%0`.

    The argument completes: type `:PromptTmuxPane ` and press <Tab>.

:PromptTerminal [name]                                       *:PromptTerminal*

    Choose the Neovim |:terminal| buffer used by `send = 'terminal'`.

    No argument  open a picker listing the terminal buffers.
    `auto`       pick one matching `agents`, else the most recent.
    A name       use the terminal whose title contains that name.

==============================================================================
REFERENCES

@buffer                                                  *prompt-send-@buffer*

    Current buffer content.

@file                                                      *prompt-send-@file*

    Current buffer's path, relative to the working directory.

@select                                                  *prompt-send-@select*

    Last Visual selection, read from the |'<| and |'>| marks (no need to
    re-enter Visual mode). Supports char, line, and block selections.

@diagnostic                                          *prompt-send-@diagnostic*

    LSP diagnostics of the current buffer.

@gitdiff                                                *prompt-send-@gitdiff*

    Unstaged changes in the repository ("git diff --no-color").

@N                                                            *prompt-send-@N*

    A literal newline. `@N` is self-delimiting, so it works right next to
    text: `a@Nb` gives `a` and `b` on separate lines. Capital `N` is
    reserved — do not start a reference name with it. `@@N` gives a literal
    `@N`.

==============================================================================
API

prompt-send.target()                                    *prompt-send.target()*

    Returns where prompts will go: a pane id (e.g. `"%0"`), `"auto"`,
    `"terminal"` for the Neovim-terminal sender, or `"command"` when a
    custom `send` is configured. It only reads in-memory state, so it is
    cheap enough for a statusline.

>lua
    'send:' .. require('prompt-send').target()
<

==============================================================================
STATUSLINE

|prompt-send.target()| returns where prompts will go. A statusline just needs
to call it where the content is built. With mini.statusline that means
rebuilding `content.active` and appending the string to a group:

>lua
      require('mini.statusline').setup({
          content = {
              active = function()
                  local sl = require('mini.statusline')
                  local mode, mode_hl = sl.section_mode({ trunc_width = 120 })
                  local git           = sl.section_git({ trunc_width = 40 })
                  local diff          = sl.section_diff({ trunc_width = 75 })
                  local diagnostics   = sl.section_diagnostics({ trunc_width = 75 })
                  local lsp           = sl.section_lsp({ trunc_width = 75 })
                  local filename      = sl.section_filename({ trunc_width = 140 })
                  local fileinfo      = sl.section_fileinfo({ trunc_width = 120 })
                  local location      = sl.section_location({ trunc_width = 75 })
                  local search        = sl.section_searchcount({ trunc_width = 75 })
                  local prompt = 'send:' .. require('prompt-send').target()
                  return sl.combine_groups({
                      { hl = mode_hl, strings = { mode } },
                      { hl = 'MiniStatuslineDevinfo', strings = { git, diff, diagnostics, lsp, prompt } },
                      '%<',
                      { hl = 'MiniStatuslineFilename', strings = { filename } },
                      '%=',
                      { hl = 'MiniStatuslineFileinfo', strings = { fileinfo } },
                      { hl = mode_hl, strings = { search, location } },
                  })
              end,
          },
      })
<

==============================================================================
RECIPES

Send to a running opencode session

    opencode's `api` subcommand handles service discovery and auth, so there
    is no shell or wrapper to write. Use a function `send` so the prompt is
    JSON-encoded:

>lua
      local session = vim.env.OPENCODE_SESSION   -- e.g. 'ses_...'

      require('prompt-send').setup({
          send = function(prompt)
              return {
                  'opencode', 'api', 'post',
                  '/api/session/' .. session .. '/prompt',
                  '--data', vim.json.encode({ text = prompt }),
              }
          end,
      })
<
    Get a session id with `opencode session list`, then start Neovim with
    `OPENCODE_SESSION=ses_... nvim`. Add `resume = false` to the JSON body to
    admit the input without running the agent.
