INTRODUCTION       *prompt-send* *prompt-send.nvim* *prompt-send-introduction*

Write a prompt in Neovim's `:` command line, fill it with editor content using
`@references`, and send it to a tmux pane, a Neovim |:terminal| buffer, or an
external command.

Features:

- Write a prompt in the `:` command line and fill it with editor content via
  `@references`. See |:PromptSend|.
- Built-in references `@buffer`, `@file`, `@select`, `@diagnostic`, `@gitdiff`
  and `@N`, plus your own. See |prompt-send-references|.
- Reference name completion and support for Visual mode.
- Three ways to send: a tmux pane, a Neovim |:terminal| buffer, or an external
  command. See |prompt-send-config-via|.

This plugin is AI-generated, with zero hand-written code. A human only
directed and reviewed it. Treat it accordingly.

==============================================================================
REQUIREMENTS                                        *prompt-send-requirements*

- Neovim 0.7 or later (developed on 0.12).
- tmux, only when sending with `via = "tmux"`.

==============================================================================
SETUP                                                      *prompt-send-setup*

Loading the module with `require('prompt-send')` registers the commands with
the default options. Call `setup()` to change them: >lua

  require('prompt-send').setup({
    via = 'tmux',
    tmux = { pane = '%3' },
  })
<
Options you leave out keep their current value. See |prompt-send-config| for
every option and its default.

A bad `via` is reported as an error, and the plugin then refuses to send until
a later `setup()` succeeds. Nothing else is validated.

==============================================================================
CONFIGURATION                 *prompt-send-config* *prompt-send-configuration*

Default values: >lua

  require('prompt-send').setup({
    via = "tmux",        -- "tmux" | "terminal" | "command"
    references = {},

    tmux = {
      pane = nil,        -- "%2" | nil (pick per send)
      enter = true,      -- append Enter
    },
    terminal = {
      enter = true,      -- append a newline
    },
    command = {
      run = nil,         -- string | fun(prompt): string|string[]
      stdin = false,     -- pass prompt via stdin instead of as the last arg
    },

    agents = {           -- names matched against pane command + title
      "opencode", "claude", "codex", "aider", "gemini", "crush", "goose",
      "cursor-agent", "openhands",
    },
  })
<

                                                      *prompt-send-config-via*
via ~

Type: string, default `"tmux"`.

How the prompt is sent. One of:

  `"tmux"`      type it into a tmux pane. See |prompt-send-config-tmux|.
  `"terminal"`  write it to a Neovim |:terminal| buffer. See
                |prompt-send-config-terminal|.
  `"command"`   run an external command. See |prompt-send-config-command|.

The tmux and terminal senders deliver a multi-line prompt as a bracketed
paste, so its newlines are inserted rather than submitted.

                                                     *prompt-send-config-tmux*
tmux ~

Type: table. Options for `via = "tmux"`.

`tmux.pane`  (string or nil, default `nil`)
    A pane id like `"%2"` to always send to. With `nil` a pane is picked on
    each send (see |prompt-send-config-agents|). |:PromptTmuxPane| overrides
    it for the current session.

`tmux.enter`  (boolean, default `true`)
    Append Enter after the prompt.

                                                 *prompt-send-config-terminal*
terminal ~

Type: table. Options for `via = "terminal"`.

`terminal.enter`  (boolean, default `true`)
    Append a newline after the prompt.

The buffer to send to is chosen with |:PromptTerminal|.

                                                  *prompt-send-config-command*
command ~

Type: table. Options for `via = "command"`.

`command.run`  (string, function or nil, default `nil`)
    The command to run. Set it before sending. It is either:
    - a string, split on whitespace into argv (no shell is involved); or
    - a function called with the resolved prompt that returns a string or an
      argv list.

`command.stdin`  (boolean, default `false`)
    Used when `command.run` is a string. `true` writes the prompt to stdin and
    closes it; `false` appends it as the last argument.

The command's stdout is discarded. A non-zero exit shows its stderr as an
error notification. Success is silent: no reply is read.

                                                   *prompt-send-config-agents*
agents ~

Type: list of strings. Names that identify an agent.

When `tmux.pane` is `nil`, each pane's `pane_current_command` and
`pane_title` are matched against these names. The first match wins; if
nothing matches, the first non-Neovim pane is used. Set `agents = {}` to skip
the name match.

The terminal sender matches `term_title` against the same names when no
buffer has been chosen with |:PromptTerminal|.

                                               *prompt-send-config-references*
references ~

Type: table, default `{}`. Maps a name to a function.

Each function takes no arguments and returns a string. They are merged over
the built-in references, and a same name overrides the built-in one.
Example: >lua

  require('prompt-send').setup({
    references = {
      git = function() return vim.fn.system('git diff') end,
    },
  })
<
Then `:PromptSend explain @git` works. See |prompt-send-reference-rules| for
what a name may contain and what counts as a failure.

==============================================================================
REFERENCES                                            *prompt-send-references*

A `@name` in a prompt is replaced with editor content before the prompt is
sent. Typing `@` on the command line completes reference names.

Built-in references:

@buffer                                                  *prompt-send-@buffer*
    Current buffer content.

@file                                                      *prompt-send-@file*
    Current buffer's path, relative to the working directory.

@select                                                  *prompt-send-@select*
    Last Visual selection, read from the |'<| and |'>| marks, so there is no
    need to re-enter Visual mode. Character, line and block selections are
    supported.

@gitdiff                                                *prompt-send-@gitdiff*
    Unstaged changes in the repository (`git diff --no-color`).

@diagnostic                                          *prompt-send-@diagnostic*
    LSP diagnostics of the current buffer.

@N                                                            *prompt-send-@N*
    A literal newline. `@N` is self-delimiting, so it works right next to
    text: `a@Nb` gives `a` and `b` on separate lines. Capital `N` is
    reserved, so do not start a reference name with it.

                                                 *prompt-send-reference-rules*
Rules ~

- A name may contain letters, digits, `_` and `-`.
- `@@` is an escape: `@@buffer` is sent as the literal `@buffer`, and `@@N`
  as the literal `@N`.
- An unknown `@name` is left as-is.
- A reference fails when its function raises an error or returns `nil`. Then
  nothing is sent and the error is shown. An empty string is a success.

==============================================================================
COMMANDS                                                *prompt-send-commands*

:PromptSend {prompt}                                             *:PromptSend*
    Send a prompt, replacing every `@reference` first. Works from Visual
    mode; the leading `'<,'>` is handled for you. >vim

      :PromptSend check @buffer
      :'<,'>PromptSend explain @select
      :PromptSend what is wrong here: @select @diagnostic
<
    Typing `@` completes reference names. See |prompt-send-references| for
    the escape and failure rules.

:PromptTmuxPane [pane]                                       *:PromptTmuxPane*
    Choose the tmux pane used by the tmux sender.

      No argument   pick a pane from a list.
      `auto`        go back to the automatic choice (see
                    |prompt-send-config-agents|).
      A pane id     always send there, e.g. `%0`.

    The argument completes: type `:PromptTmuxPane ` and press <Tab>.

:PromptTerminal [name]                                       *:PromptTerminal*
    Choose the Neovim |:terminal| buffer used by the terminal sender.

      No argument   open a picker listing the terminal buffers.
      `auto`        pick one matching `agents`, else the most recent.
      A name        use the terminal whose title contains that name.

==============================================================================
API                                                          *prompt-send-api*

prompt-send.target({opts})                              *prompt-send.target()*
    Return where prompts will go: a pane id (e.g. `"%0"`) or `"auto"` for the
    tmux sender, `"terminal"`, or `"command"`. It only reads in-memory state,
    so it is cheap enough for a statusline.

    `opts` is an optional table. With `opts.short = true`, `"auto"`,
    `"terminal"` and `"command"` become the short labels `"A"`, `"T"` and
    `"C"`. A pinned pane id is already short and is returned unchanged. >lua

      'send:' .. require('prompt-send').target()
      'send:' .. require('prompt-send').target({ short = true })
<

RECIPES                                                  *prompt-send-recipes*

                                               *prompt-send-recipe-statusline*
Statusline ~

With mini.statusline, rebuild `content.active` and add |prompt-send.target()|
to a group: >lua

  require('mini.statusline').setup({
    content = {
      active = function()
        local sl = require('mini.statusline')
        local mode, mode_hl = sl.section_mode({ trunc_width = 120 })
        local git           = sl.section_git({ trunc_width = 40 })
        local diff          = sl.section_diff({ trunc_width = 75 })
        local diagnostics   = sl.section_diagnostics({ trunc_width = 75 })
        local lsp           = sl.section_lsp({ trunc_width = 75 })
        local filename      = sl.section_filename({ trunc_width = 140 })
        local fileinfo      = sl.section_fileinfo({ trunc_width = 120 })
        local location      = sl.section_location({ trunc_width = 75 })
        local search        = sl.section_searchcount({ trunc_width = 75 })
        local prompt = 'send:' .. require('prompt-send').target()
        return sl.combine_groups({
          { hl = mode_hl, strings = { mode } },
          { hl = 'MiniStatuslineDevinfo',
            strings = { git, diff, diagnostics, lsp, prompt } },
          '%<',
          { hl = 'MiniStatuslineFilename', strings = { filename } },
          '%=',
          { hl = 'MiniStatuslineFileinfo', strings = { fileinfo } },
          { hl = mode_hl, strings = { search, location } },
        })
      end,
    },
  })
<
                                                 *prompt-send-recipe-opencode*
Send to a running opencode session ~

opencode's `api` subcommand handles service discovery and auth, so there is no
shell or wrapper to write. Use a function for `command.run` so the prompt is
JSON-encoded: >lua

  local session = vim.env.OPENCODE_SESSION   -- e.g. 'ses_...'

  require('prompt-send').setup({
    via = 'command',
    command = {
      run = function(prompt)
        return {
          'opencode', 'api', 'post',
          '/api/session/' .. session .. '/prompt',
          '--data', vim.json.encode({ text = prompt }),
        }
      end,
    },
  })
<
Get a session id with `opencode session list`, then start Neovim with
`OPENCODE_SESSION=ses_... nvim`. Add `resume = false` to the JSON body to
admit the input without running the agent.
