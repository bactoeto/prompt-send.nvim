==============================================================================
INTRODUCTION       *prompt-send* *prompt-send.nvim* *prompt-send-introduction*

Use |:PromptSend| to fill `@references` with editor content and send a prompt
to tmux, a Neovim |:terminal| buffer, or an external command.

==============================================================================
REQUIREMENTS                                        *prompt-send-requirements*

- Neovim 0.7 or later (developed on 0.12).
- tmux, only when sending with `via = "tmux"`.

==============================================================================
SETUP                                                      *prompt-send-setup*

`require('prompt-send')` registers the commands with default options. To
change them: >lua

  require('prompt-send').setup({ tmux = { pane = '%3' } })
<
Omitted options retain their current values. An invalid `via` disables sending
until a later `setup()` succeeds; other options are not validated. See
|prompt-send-config| for defaults.

==============================================================================
CONFIGURATION                 *prompt-send-config* *prompt-send-configuration*

Default values: >lua

  require('prompt-send').setup({
    via = "tmux",        -- "tmux" | "terminal" | "command"
    references = {},

    tmux = {
      pane = nil,        -- "%2" | nil (pick per send)
      enter = true,      -- append Enter
    },
    terminal = {
      enter = true,      -- append a newline
    },
    command = {
      run = nil,         -- string | fun(prompt): string|string[]
      stdin = false,     -- pass prompt via stdin instead of as the last arg
    },

    agents = {           -- names matched against pane command + title
      "opencode", "claude", "codex", "aider", "gemini", "crush", "goose",
      "cursor-agent", "openhands",
    },
  })
<

                                                      *prompt-send-config-via*
via ~

Type: string, default `"tmux"`.

  `"tmux"`      send to a tmux pane. See |prompt-send-config-tmux|.
  `"terminal"`  send to a Neovim |:terminal| buffer. See
                |prompt-send-config-terminal|.
  `"command"`   run an external command. See |prompt-send-config-command|.

Tmux and terminal use bracketed paste for multi-line prompts.

                                                     *prompt-send-config-tmux*
tmux ~

`tmux.pane`  (string or nil, default `nil`)
    Pin a pane id such as `"%2"`; `nil` picks per send (see
    |prompt-send-config-agents|). Change it with |:PromptTmuxPane|.

`tmux.enter`  (boolean, default `true`)
    Append Enter after the prompt.

                                                 *prompt-send-config-terminal*
terminal ~

`terminal.enter`  (boolean, default `true`)
    Append a newline after the prompt. Choose a buffer with |:PromptTerminal|.

                                                  *prompt-send-config-command*
command ~

`command.run`  (string, function or nil, default `nil`)
    Required for sending. A string is split on whitespace (no shell); a
    function receives the resolved prompt and returns a string or argv list.

`command.stdin`  (boolean, default `false`)
    For string commands: `true` writes the prompt to stdin; `false` appends
    it as the last argument. Functions handle the prompt themselves.

Stdout is discarded; a non-zero exit reports stderr. Success is silent.

                                                   *prompt-send-config-agents*
agents ~

Type: list of strings. For automatic tmux selection, match pane command and
title; use the first matching pane, or the first non-Neovim pane. For terminal
selection, match `term_title`, or use the most recent buffer. Set
`agents = {}` to skip matching.

                                               *prompt-send-config-references*
references ~

Type: table, default `{}`. Map names to zero-argument functions returning
strings. Custom names override built-in references. For example: >lua

  require('prompt-send').setup({
    references = { git = function() return vim.fn.system('git diff') end },
  })
<
See |prompt-send-reference-rules| for name and failure rules.

==============================================================================
REFERENCES                                            *prompt-send-references*

`@name` is resolved before sending. Typing `@` completes reference names.

Built-in references:

@buffer                                                  *prompt-send-@buffer*
    Current buffer content.

@file                                                      *prompt-send-@file*
    Current buffer's path, relative to the working directory.

@select                                                  *prompt-send-@select*
    Last Visual selection (character, line or block), from |'<| and |'>|.

@gitdiff                                                *prompt-send-@gitdiff*
    Unstaged changes in the repository (`git diff --no-color`).

@diagnostic                                          *prompt-send-@diagnostic*
    LSP diagnostics of the current buffer.

@N                                                            *prompt-send-@N*
    A literal newline. Self-delimiting: `a@Nb` puts `a` and `b` on separate
    lines. Names cannot start with capital `N`.

                                                 *prompt-send-reference-rules*
Rules ~

- A name may contain letters, digits, `_` and `-`.
- `@@` escapes `@`: `@@buffer` sends the literal `@buffer`.
- Unknown `@name` is left as-is.
- If a function errors or returns `nil`, nothing is sent and an error is
  shown. An empty string is valid.

==============================================================================
COMMANDS                                                *prompt-send-commands*

:PromptSend {prompt}                                             *:PromptSend*
    Resolve |prompt-send-references| and send. Works from Visual mode; the
    leading `'<,'>` is ignored. >vim

      :PromptSend check @buffer
      :'<,'>PromptSend explain @select
<

:PromptTmuxPane [pane]                                       *:PromptTmuxPane*
    Choose the tmux pane used by the tmux sender.

      No argument   pick a pane from a list.
      `auto`        go back to the automatic choice (see
                    |prompt-send-config-agents|).
      A pane id     always send there, e.g. `%0`.

    Pane ids and `auto` complete with <Tab>.

:PromptTerminal [name]                                       *:PromptTerminal*
    Choose the Neovim |:terminal| buffer used by the terminal sender.

      No argument   open a picker listing the terminal buffers.
      `auto`        pick one matching `agents`, else the most recent.
      A name        use the terminal whose title contains that name.

==============================================================================
API                                                          *prompt-send-api*

prompt-send.target({opts})                              *prompt-send.target()*
    Return where prompts will go: a pane id (e.g. `"%0"`) or `"auto"` for the
    tmux sender, `"terminal"`, or `"command"`. It only reads in-memory state,
    so it is cheap enough for a statusline.

    `opts` is an optional table. With `opts.short = true`, `"auto"`,
    `"terminal"` and `"command"` become the short labels `"A"`, `"T"` and
    `"C"`. A pinned pane id is already short and is returned unchanged. >lua

      'send:' .. require('prompt-send').target()
      'send:' .. require('prompt-send').target({ short = true })
<

==============================================================================
RECIPES                                                  *prompt-send-recipes*

                                               *prompt-send-recipe-statusline*
Statusline ~

With mini.statusline, rebuild `content.active` and add |prompt-send.target()|
to a group: >lua

  require('mini.statusline').setup({
    content = {
      active = function()
        local sl = require('mini.statusline')
        local mode, mode_hl = sl.section_mode({ trunc_width = 120 })
        local git           = sl.section_git({ trunc_width = 40 })
        local diff          = sl.section_diff({ trunc_width = 75 })
        local diagnostics   = sl.section_diagnostics({ trunc_width = 75 })
        local lsp           = sl.section_lsp({ trunc_width = 75 })
        local filename      = sl.section_filename({ trunc_width = 140 })
        local fileinfo      = sl.section_fileinfo({ trunc_width = 120 })
        local location      = sl.section_location({ trunc_width = 75 })
        local search        = sl.section_searchcount({ trunc_width = 75 })
        local prompt = 'send:' .. require('prompt-send').target()
        return sl.combine_groups({
          { hl = mode_hl, strings = { mode } },
          { hl = 'MiniStatuslineDevinfo',
            strings = { git, diff, diagnostics, lsp, prompt } },
          '%<',
          { hl = 'MiniStatuslineFilename', strings = { filename } },
          '%=',
          { hl = 'MiniStatuslineFileinfo', strings = { fileinfo } },
          { hl = mode_hl, strings = { search, location } },
        })
      end,
    },
  })
<
                                                 *prompt-send-recipe-opencode*
Send to a running opencode session ~

opencode's `api` subcommand handles service discovery and auth, so there is no
shell or wrapper to write. Use a function for `command.run` so the prompt is
JSON-encoded: >lua

  local session = vim.env.OPENCODE_SESSION   -- e.g. 'ses_...'

  require('prompt-send').setup({
    via = 'command',
    command = {
      run = function(prompt)
        return {
          'opencode', 'api', 'post',
          '/api/session/' .. session .. '/prompt',
          '--data', vim.json.encode({ text = prompt }),
        }
      end,
    },
  })
<
Get a session id with `opencode session list`, then start Neovim with
`OPENCODE_SESSION=ses_... nvim`. Add `resume = false` to the JSON body to
admit the input without running the agent.
